# Linux Kernel `nsproxy` 與多種 Namespace 測試

## 1. 目的

這個實驗要驗證：

> 一個 Process 可以同時屬於多種不同類型的 Namespace。

例如：

```text
Process
   │
   ▼
task_struct
   │
   ▼
nsproxy
   │
   ├── Network Namespace
   ├── Mount Namespace
   ├── UTS Namespace
   ├── IPC Namespace
   ├── PID Namespace
   ├── Time Namespace
   └── Cgroup Namespace
```

`nsproxy` 本身不是 Namespace，而是保存多種 Namespace reference 的資料結構。

---

# 2. Kernel `struct nsproxy`

Linux Kernel 可以從：

```text
include/linux/nsproxy.h
```

開始看。

核心資料結構概念如下：

```c
struct nsproxy {
    atomic_t count;

    struct uts_namespace *uts_ns;
    struct ipc_namespace *ipc_ns;
    struct mnt_namespace *mnt_ns;

    struct pid_namespace *pid_ns_for_children;

    struct net *net_ns;

    struct time_namespace *time_ns;
    struct time_namespace *time_ns_for_children;

    struct cgroup_namespace *cgroup_ns;
};
```

因此：

```text
                    struct nsproxy
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
       uts_ns           mnt_ns           net_ns
          │                │                │
          ▼                ▼                ▼
     UTS Namespace    Mount Namespace   Network Namespace

          │                │                │
          ▼                ▼                ▼
       ipc_ns          pid_ns           cgroup_ns
```

---

# 3. 查看目前 Process 的 Namespace

先查看目前 shell PID：

```bash
echo $$
```

例如：

```text
12345
```

查看這個 process 使用的 Namespace：

```bash
ls -l /proc/$$/ns/
```

可能看到：

```text
cgroup -> cgroup:[4026531835]
ipc    -> ipc:[4026531839]
mnt    -> mnt:[4026531841]
net    -> net:[4026531840]
pid    -> pid:[4026531836]
time   -> time:[4026531834]
user   -> user:[4026531837]
uts    -> uts:[4026531838]
```

這已經可以看到：

```text
同一個 Process
      │
      ├── cgroup namespace
      ├── IPC namespace
      ├── mount namespace
      ├── network namespace
      ├── PID namespace
      ├── time namespace
      ├── user namespace
      └── UTS namespace
```

---

# 4. 查看各 Namespace ID

分別執行：

```bash
readlink /proc/$$/ns/net
readlink /proc/$$/ns/uts
readlink /proc/$$/ns/mnt
readlink /proc/$$/ns/pid
```

例如：

```text
net:[4026531840]
uts:[4026531838]
mnt:[4026531841]
pid:[4026531836]
```

可以先記錄下來。

---

# 5. 建立新的 Namespace

使用：

```bash
sudo unshare --net --uts --mount bash
```

這代表建立新的：

```text
Network Namespace
UTS Namespace
Mount Namespace
```

然後在新的 Namespace context 裡啟動：

```text
bash
```

概念：

```text
原本 Shell
   │
   │ unshare
   ▼
新的 Shell
   │
   ├── New NET Namespace
   ├── New UTS Namespace
   └── New MNT Namespace
```

---

# 6. 再次查看 Namespace

進入新的 shell 後：

```bash
echo $$
```

然後：

```bash
readlink /proc/$$/ns/net
readlink /proc/$$/ns/uts
readlink /proc/$$/ns/mnt
readlink /proc/$$/ns/pid
```

例如可能看到：

```text
net:[4026533001]
uts:[4026533002]
mnt:[4026533003]
pid:[4026531836]
```

跟原本比較：

```text
原本：

net:[4026531840]
uts:[4026531838]
mnt:[4026531841]
pid:[4026531836]


unshare 後：

net:[4026533001]    ← 改變
uts:[4026533002]    ← 改變
mnt:[4026533003]    ← 改變
pid:[4026531836]    ← 沒改變
```

原因是我們執行：

```bash
unshare --net --uts --mount
```

沒有指定：

```bash
--pid
```

# 7. `nsproxy` 的變化

原本：

```text
Process A
   │
   ▼
task_struct
   │
   ▼
nsproxy
   │
   ├── net_ns ──────→ NET A
   ├── uts_ns ──────→ UTS A
   ├── mnt_ns ──────→ MNT A
   └── pid_ns ──────→ PID A
```

執行：

```bash
unshare --net --uts --mount
```

之後可以概念化成：

```text
Process B
   │
   ▼
task_struct
   │
   ▼
nsproxy
   │
   ├── net_ns ──────→ NET B    ★ 新
   ├── uts_ns ──────→ UTS B    ★ 新
   ├── mnt_ns ──────→ MNT B    ★ 新
   └── pid_ns ──────→ PID A    ← 沿用
```

所以：

```text
unshare
```

不一定要把所有 Namespace 都建立新的。

可以只替換其中幾種類型。

---

# 8. 驗證 Network Namespace

因為使用：

```bash
unshare --net
```

所以目前 shell 位於新的 Network Namespace。

執行：

```bash
ip addr
```

通常一開始只會看到：

```text
lo
```

例如：

```text
1: lo: <LOOPBACK>
```

而且可能是：

```text
state DOWN
```

這是因為新的 Network Namespace 沒有原本 Host 的：

```text
eth0
wlan0
eno1
...
```

---

# 9. 為什麼看不到原本網卡？

原本可能是：

```text
Default Network Namespace
│
├── lo
├── eth0
└── wlan0
```

執行：

```bash
unshare --net
```

之後：

```text
New Network Namespace
│
└── lo
```

因為 network device 屬於特定 Network Namespace。

所以新的 Network Namespace 不會自動看到原本 Namespace 的網卡。

---

# 10. 驗證 UTS Namespace

UTS Namespace 主要隔離：

```text
hostname
domain name
```

查看：

```bash
hostname
```

例如：

```text
nickhuang
```

修改：

```bash
hostname ns-test
```

再次查看：

```bash
hostname
```

得到：

```text
ns-test
```

目前關係：

```text
New UTS Namespace
      │
      └── hostname = ns-test
```

---

# 11. 離開 Namespace

執行：

```bash
exit
```

回到原本 shell。

再次：

```bash
hostname
```

應該會看到原本 hostname。

例如：

```text
nickhuang
```

而不是：

```text
ns-test
```

因為：

```text
原本 Shell
   │
   └── UTS Namespace A
          hostname = nickhuang


unshare Shell
   │
   └── UTS Namespace B
          hostname = ns-test
```

兩者是不同的 UTS Namespace。

---

# 12. 只建立 Network Namespace

如果只想測 Network Namespace：

```bash
sudo unshare --net bash
```

查看：

```bash
readlink /proc/$$/ns/net
```

以及：

```bash
ip addr
```

其他 Namespace 通常仍沿用原來的 Namespace。

---

# 13. 只建立 UTS Namespace

```bash
sudo unshare --uts bash
```

然後：

```bash
hostname test
hostname
```

退出：

```bash
exit
```

外面的 hostname 不受影響。

---

# 14. 建立 PID Namespace

PID Namespace 有一個重要差異。

通常搭配：

```bash
sudo unshare --pid --fork bash
```

如果希望 `/proc` 也反映新的 PID Namespace，可以進一步使用：

```bash
sudo unshare --pid --fork --mount-proc bash
```

然後：

```bash
ps aux
```

可以觀察新的 PID view。

PID Namespace 比 NET / UTS Namespace 多了 parent/child namespace 的概念，因此值得獨立研究。

---

# 15. 一次建立多種 Namespace

例如：

```bash
sudo unshare \
    --net \
    --uts \
    --mount \
    --ipc \
    --pid \
    --fork \
    --mount-proc \
    bash
```

這時新的 shell 會使用多種新的 Namespace。

概念：

```text
New Process
     │
     ▼
  task_struct
     │
     ▼
   nsproxy
     │
     ├── NET Namespace B
     ├── UTS Namespace B
     ├── MNT Namespace B
     ├── IPC Namespace B
     └── PID Namespace B
```

# 16. `nsproxy` 與 Process

Kernel 中可以概念化為：

```text
struct task_struct
        │
        │ nsproxy
        ▼
struct nsproxy
        │
        ├── uts_ns
        │      ↓
        │   UTS Namespace
        │
        ├── ipc_ns
        │      ↓
        │   IPC Namespace
        │
        ├── mnt_ns
        │      ↓
        │   Mount Namespace
        │
        ├── pid_ns_for_children
        │      ↓
        │   PID Namespace
        │
        ├── net_ns
        │      ↓
        │   struct net
        │
        └── cgroup_ns
               ↓
           Cgroup Namespace
```

因此：

> `nsproxy` 是 Process 使用的一組 Namespace references。

---

# 17. 一個 `nsproxy` 可以有多個 Network Namespace 嗎？

不行。

例如：

```c
struct net *net_ns;
```

只有一個 pointer。

因此不是：

```text
nsproxy
   │
   └── net_ns
          ├── nsA
          └── nsB
```

而是：

```text
Process A
   │
   ▼
nsproxy A
   │
   └── net_ns ─────→ nsA
```

以及：

```text
Process B
   │
   ▼
nsproxy B
   │
   └── net_ns ─────→ nsB
```

但是一個 `nsproxy` 可以同時 reference：

```text
一個 Network Namespace
一個 Mount Namespace
一個 UTS Namespace
一個 IPC Namespace
...
```

---

# 18. 多個 Process 可以共用 Namespace

例如：

```text
                Network Namespace A
                       ▲
                       │
                  struct net
                    ▲     ▲
                    │     │
              Process A  Process B
```

因此 Namespace 並不是：

```text
一個 Namespace = 一個 Process
```

而是可以：

```text
多個 Process
      ↓
共享同一個 Namespace
```

例如：

```text
nsA
│
├── bash
├── ping
├── tcpdump
└── python
```

都可以使用同一個 Network Namespace。

# 22. 重點

最重要的觀念可以整理成：

```text
Process
   │
   ▼
task_struct
   │
   ▼
nsproxy
   │
   ├── Network Namespace
   ├── UTS Namespace
   ├── Mount Namespace
   ├── IPC Namespace
   ├── PID Namespace
   ├── Time Namespace
   └── Cgroup Namespace
```

`nsproxy`：

```text
不是 Namespace 本身
```

而是：

```text
Process 使用的一組 Namespace references
```

`unshare()` 則可以：

```text
原本 Namespace references
          │
          ▼
選擇其中某些 Namespace
          │
          ▼
建立新的 Namespace
          │
          ▼
Process 開始使用新的 Namespace
```

因此 `unshare --net --uts --mount` 是一個非常直觀的實驗，可以驗證：

> 同一個 Process 可以同時使用多種不同類型的 Namespace，而且可以只替換其中部分 Namespace。
