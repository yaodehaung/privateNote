# Linux Kernel RTNL、`rtnl_link_ops` 與 `net_device`

## 1. 整體架構

Linux userspace 可以透過 `ip` 指令控制 Kernel networking：

```bash id="4k46ym"
ip link
ip addr
ip route
ip neigh
```

這些操作大量透過：

```text id="6uw2tm"
NETLINK_ROUTE
```

進入 Kernel。

整體概念：

```text id="s8f50f"
Userspace
   │
   │ ip link / ip addr / ip route
   │
   ▼
NETLINK_ROUTE
   │
   ▼
rtnetlink / RTNL
   │
   ├───────────────┐
   ▼               ▼
rtnl_link_ops   struct net_device
   │               │
   │               ▼
   │         net_device_ops
   │               │
   ▼               ▼
建立/刪除 Link    Device 實際操作
```

---

# 2. `rtnetlink` 是什麼？

`rtnetlink` 是 Linux Kernel networking 的 Netlink 控制介面之一。

主要處理：

```text id="fr5dy5"
link
address
route
neighbour
...
```

userspace：

```bash id="3c4zkg"
ip link
ip addr
ip route
ip neigh
```

透過：

```text id="uqg8hk"
NETLINK_ROUTE
```

和 Kernel 通訊。

主要 Kernel source：

```text id="mm5m8b"
net/core/rtnetlink.c
include/net/rtnetlink.h
```

---

# 3. `ip` 與 rtnetlink

例如：

```bash id="9pru3t"
ip link add veth0 type veth peer name veth1
```

概念流程：

```text id="ikxkzv"
ip
 │
 │ NETLINK_ROUTE
 ▼
Kernel
 │
 ▼
rtnetlink
 │
 │ RTM_NEWLINK
 ▼
rtnl_link_ops
 │
 ▼
veth_newlink()
```

所以：

```text id="t0u0jj"
ip
```

本身並不是直接呼叫：

```c id="39h8f8"
veth_newlink()
```

而是：

```text id="a6zuvl"
ip
 ↓
Netlink message
 ↓
NETLINK_ROUTE
 ↓
rtnetlink
 ↓
找到對應 link type
 ↓
driver callback
```

# 4. RTNL 是什麼？

Linux networking 裡還經常看到：

```c id="lajv14"
rtnl_lock();
```

以及：

```c id="25f8fs"
rtnl_unlock();
```

RTNL lock 是 Linux networking configuration 很重要的同步機制。

概念：

```c id="6lcs4a"
rtnl_lock();

/* 修改 networking configuration */

rtnl_unlock();
```

可能看到：

```c id="xawhmh"
ASSERT_RTNL();
```

代表這段程式碼預期 caller 已經持有 RTNL lock。

所以要區分：

```text id="onqojt"
rtnetlink
    ↓
Netlink networking control interface

RTNL lock
    ↓
Networking configuration synchronization
```

# 5. `struct net_device` 是什麼？

Linux Kernel 使用：

```c id="dlml2h"
struct net_device
```

代表一個 network interface。

定義主要在：

```text id="id4kyq"
include/linux/netdevice.h
```

例如：

```text id="5y77rc"
eth0
wlan0
lo
veth0
dummy0
bridge0
```

在 Kernel 裡都會有對應的 `struct net_device`。

概念：

```text id="itohgc"
Userspace                Kernel

eth0        ──────────→  struct net_device
wlan0       ──────────→  struct net_device
veth0       ──────────→  struct net_device
lo          ──────────→  struct net_device
```

# 7. `struct net_device_ops`

Network driver 可以透過：

```c id="ue04zq"
struct net_device_ops
```

提供 device operations。

例如：

```c id="sy8dfq"
static const struct net_device_ops example_netdev_ops = {
    .ndo_open       = example_open,
    .ndo_stop       = example_stop,
    .ndo_start_xmit = example_xmit,
};
```

然後：

```c id="n8e5v1"
dev->netdev_ops = &example_netdev_ops;
```

# 9. `struct rtnl_link_ops`

`rtnl_link_ops` 則是另一個概念。

主要定義：

```text id="u7eqzw"
include/net/rtnetlink.h
```

它主要描述：

> 某一種 network link type 要如何建立、修改與刪除。

例如：

```text id="2zw6gp"
veth
dummy
bridge
vlan
ipvlan
macvlan
```

這些 logical/virtual link type 可以向 rtnetlink 註冊自己的操作。

# 11. `.kind = "veth"` 有什麼作用？

當 userspace 執行：

```bash id="9ozt4g"

```

這裡：

```text id="c1jnag"
type veth
     ^^^^
```

會讓 Kernel 找到：

```c id="1u19s7"
.kind = "veth"
```

對應的：

```text id="zhz0h5"

```

然後呼叫：

```c id="g1f2bo"
veth_newlink()
```

概念：

```text id="p3qqce"
ip link add ... type veth
              │
              ▼
        NETLINK_ROUTE
              │
              ▼
          rtnetlink
              │
              │ "veth"
              ▼
       veth_link_ops
              │
              ▼
        .newlink
              │
              ▼
       veth_newlink()
```

# 12. `rtnl_link_ops` vs `net_device_ops`

這兩個非常容易搞混。

## `rtnl_link_ops`

主要回答：

> 這種 network link 要怎麼建立、修改、刪除？

例如：

```text id="13v2t6"
.newlink
.dellink
.changelink
.validate
.setup
```

主要偏向：

```text id="5tgblt"
Control Plane
```

---

## `net_device_ops`

主要回答：

> 這個 network device 建立後要怎麼運作？

例如：

```text id="mbdtd7"
.ndo_open
.ndo_stop
.ndo_start_xmit
.ndo_change_mtu
```

主要偏向：

```text id="p6nx5r"
Device operations / Data path
```

---

# 13. 兩者關係

可以理解成：

```text id="djtr2r"
              rtnetlink
                  │
                  ▼
          rtnl_link_ops
                  │
                  │ 建立
                  ▼
        struct net_device
                  │
                  ▼
         net_device_ops
                  │
                  ▼
             Driver
```

簡單記：

```text id="72n8ca"
rtnl_link_ops
    ↓
怎麼建立這種 device/link？

net_device_ops
    ↓
device 建好後怎麼工作？
```

# 15. veth 傳送封包

device 建立完成後，送封包就不是 `rtnl_link_ops` 的主要工作了。

例如：

```bash id="93qlz3"

```

TX path：

```text id="axg6nr"
ping
 │
 ▼
ICMP
 │
 ▼
IPv4
 │
 ▼
Neighbour / Ethernet
 │
 ▼
dev_queue_xmit()
 │
 ▼
struct net_device
 │
 ▼
net_device_ops
 │
 │ ndo_start_xmit
 ▼
veth_xmit()
 │
 ▼
peer veth
```

所以：

```text id="ndujsv"

    ↓
rtnl_link_ops

傳送 packet
    ↓
net_device_ops
```

# 21. 一句話整理

```text id="hn3uz4"
rtnetlink
    =
Userspace 控制 Kernel networking 的介面

rtnl_link_ops
    =
某種 network link 如何建立 / 刪除 / 修改

struct net_device
    =
Kernel 裡代表一個 network interface 的物件

net_device_ops
    =
network device 建立之後如何實際工作
```

以 veth 為例：

```text id="1rnt1d"
ip link add ... type veth
        ↓
NETLINK_ROUTE
        ↓
rtnetlink
        ↓
rtnl_link_ops
        ↓
veth_newlink()
        ↓
struct net_device
        ↓
net_device_ops
        ↓
veth_xmit()
```
