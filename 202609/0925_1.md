# Linux Kernel `devpts` 管理機制

## 1. `devpts` 是什麼？

`devpts` 是 Linux Kernel 提供的虛擬檔案系統，主要用來管理 **Pseudo Terminal Slave（PTS）**。

我們平常看到的：

```text
/dev/pts/0
/dev/pts/1
/dev/pts/2
```

就是由 `devpts` filesystem 管理的。

可以使用：

```bash
findmnt /dev/pts
```

查看目前的 `devpts`：

```text
TARGET   SOURCE FSTYPE OPTIONS
/dev/pts devpts devpts rw,nosuid,noexec,...
```

Kernel 主要實作位於：

```text
fs/devpts/inode.c
```

而 PTY driver 本身主要位於：

```text
drivers/tty/pty.c
```

---

# 2. PTY、PTMX、PTS 與 devpts 的關係

一組 PTY 包含：

```text
          PTY Pair

     Master       Slave
       │             │
       │             └── /dev/pts/N
       │
       └── master fd
```

Userspace 通常透過：

```text
/dev/ptmx
```

要求 Kernel 建立新的 PTY。

例如：

```c
int fd = open("/dev/ptmx", O_RDWR);
```

Kernel 建立：

```text
               open("/dev/ptmx")
                       │
                       ▼
                  Linux Kernel
                       │
                 allocate PTY
                       │
              ┌────────┴────────┐
              ▼                 ▼
         PTY Master         PTY Slave
              │                 │
          master fd         /dev/pts/3
```

其中：

- PTY Master 通常給 Terminal Emulator、`sshd` 等程式使用。
- PTY Slave 則模擬一般 TTY，提供給 `bash`、`zsh` 等程式使用。
- `devpts` 負責管理 `/dev/pts/N`。

---

# 3. `devpts` 如何管理 PTS？

`devpts` 的主要工作可以分成：

```text
1. 配置 PTS index
2. 建立 /dev/pts/N
3. 管理 inode
4. 關聯 PTY slave
5. 管理權限
6. PTY 關閉時刪除節點
7. 回收 index
```

完整生命週期大致為：

```text
open("/dev/ptmx")
       │
       ▼
   ptmx_open()
       │
       ▼
devpts_new_index()
       │
       │
       └── allocate N
              │
              ▼
         建立 PTY pair
              │
              ▼
       devpts_pty_new()
              │
              ▼
         /dev/pts/N
              │
              ▼
       userspace 使用
              │
              ▼
         PTY close
              │
              ▼
      devpts_pty_kill()
              │
              ▼
      devpts_kill_index()
```

---

# 4. `devpts_new_index()`

當程式：

```c
open("/dev/ptmx", O_RDWR);
```

Kernel 進入：

```text
drivers/tty/pty.c
```

中的：

```c
ptmx_open()
```

之後需要替新的 PTY slave 找一個編號。

這部分會使用 `devpts` 的 index 管理機制。

例如目前存在：

```text
/dev/pts/0
/dev/pts/1
/dev/pts/2
```

新的 PTY 可能取得：

```text
index = 3
```

之後對應的 slave 就會是：

```text
/dev/pts/3
```

因此 `/dev/pts/N` 中的 `N` 並不是 userspace 自己指定，而是由 Kernel/devpts 配置。

可以從：

```bash
git grep "devpts_new_index"
```

開始追相關程式碼。

---

# 5. `devpts_pty_new()`

取得 index 並建立 PTY 後，Kernel 還需要讓 userspace 能夠看到 slave。

例如：

```text
PTY slave
    │
    ▼
devpts_pty_new()
    │
    ├── 建立 inode
    ├── 設定 owner
    ├── 設定 group
    ├── 設定 mode
    └── 關聯 tty
    │
    ▼
/dev/pts/3
```

因此：

```bash
ls -l /dev/pts
```

可能看到：

```text
crw--w---- 1 nick tty 136, 0 ... 0
crw--w---- 1 nick tty 136, 1 ... 1
crw--w---- 1 nick tty 136, 2 ... 2
```

這些不是硬碟上的普通檔案，而是 `devpts` filesystem 動態管理的 terminal device nodes。

---

# 6. `/dev/pts/N` 如何找到真正的 PTY？

`/dev/pts/3` 只是一個 userspace 可以看到的 filesystem entry。

Kernel 還需要知道：

```text
/dev/pts/3
     │
     ▼
devpts inode
     │
     ▼
TTY / PTY slave
```

因此 devpts inode 會保存與對應 PTY/TTY 有關的資訊。

當程式：

```c
open("/dev/pts/3", O_RDWR);
```

Kernel 才能根據這個 device node 找到正確的 PTY slave。

最後資料流可以形成：

```text
Terminal Emulator
       │
       ▼
  PTY Master
       │
       ▼
   PTY core
       │
       ▼
  PTY Slave
       │
       ▼
 /dev/pts/3
       │
       ▼
      bash
```

---

# 7. PTY 關閉時如何清除？

當 terminal emulator 關閉 master：

```text
Terminal Emulator
       │
       X
 close(master)
```

PTY 開始被釋放。

devpts 也需要移除對應的 slave node：

```text
PTY close
    │
    ▼
devpts_pty_kill()
    │
    ▼
移除 /dev/pts/3
    │
    ▼
devpts_kill_index()
    │
    ▼
index 3 可再次使用
```

因此關閉 Terminal 後：

```bash
ls /dev/pts
```

原本對應的 `/dev/pts/N` 通常也會消失。

---

# 8. 每個 devpts mount 可以有自己的 PTY 空間

`devpts` 不只是單純建立 `/dev/pts/N`。

不同的 `devpts` mount instance 可以維護各自的 PTY/index 空間。

概念上：

```text
Host
│
└── /dev/pts
    ├── 0
    ├── 1
    └── 2


Container
│
└── /dev/pts
    ├── 0
    └── 1
```

這使 container 可以擁有自己的 pseudo-terminal 環境，而不必單純共用 host 所看到的全部 `/dev/pts`。

# 9. Kernel Source

PTY driver：

```text
drivers/tty/pty.c
```

主要負責：

```text
PTY Master
     ↕
PTY Slave
```

devpts filesystem：

```text
fs/devpts/inode.c
```

主要負責：

```text
PTY Slave
    │
    ▼
/dev/pts/N
```

因此可以簡單記成：

```text
drivers/tty/pty.c
       │
       │ PTY 行為
       ▼
Master ↔ Slave
          │
          │
          ▼
 fs/devpts/inode.c
          │
          │ filesystem 管理
          ▼
     /dev/pts/N
```

# 10. 建議的 Kernel Call Flow

閱讀 Linux Kernel source 時，可以按照下面順序追：

```text
Userspace

open("/dev/ptmx")
       │
       ▼

drivers/tty/pty.c

ptmx_open()
       │
       ▼

fs/devpts/inode.c

devpts_new_index()
       │
       │ allocate N
       ▼

drivers/tty/tty_io.c

tty_init_dev()
       │
       ▼

drivers/tty/pty.c

PTY initialization
       │
       ▼

fs/devpts/inode.c

devpts_pty_new()
       │
       ▼

/dev/pts/N
```

關閉時則可以繼續追：

```text
PTY close
    │
    ▼
devpts_pty_kill()
    │
    ▼
devpts_kill_index()
    │
    ▼
PTS index 回收
```

# 11. 總結

可以把整個架構記成：

```text
              /dev/ptmx
                   │
                   │ open()
                   ▼
              ptmx_open()
                   │
                   ▼
          devpts_new_index()
                   │
                   ▼
             PTY Pair
          ┌────────┴────────┐
          │                 │
      PTY Master        PTY Slave
          │                 │
          │                 ▼
          │          devpts_pty_new()
          │                 │
          │                 ▼
          │            /dev/pts/N
          │                 │
          ▼                 ▼
 Terminal Emulator         bash
```

最簡單的理解方式是：

> `pty.c` 負責 PTY Master / Slave 本身如何運作，而 `devpts` 負責管理並呈現 `/dev/pts/N`。

也就是：

```text
ptmx
  ↓
建立 PTY
  ↓
Master ↔ Slave
           ↓
         devpts
           ↓
      /dev/pts/N
```
