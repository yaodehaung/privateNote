# Linux Kernel UAPI Header

**Author:** Nick Huang
**Date:** 2026-09-13

## UAPI 是什麼？

`UAPI` 全名是：

```text
User-space API
```

Linux Kernel 使用 `uapi/` 目錄來區分：

* Kernel 內部使用的 Header
* 可以提供給 User Space 使用的 Header

例如：

```text
arch/x86/include/
│
├── asm/
│   └── setup.h
│       ↑
│       Kernel internal header
│
└── uapi/
    └── asm/
        └── boot.h
            ↑
            x86 UAPI header
```

簡單來說：

```text
include/
    ↓
Kernel Header

include/uapi/
    ↓
User Space API Header
```

Architecture-specific Header 也是相同概念：

```text
arch/<arch>/include/asm/
        ↓
Architecture-specific Kernel Header

arch/<arch>/include/uapi/asm/
        ↓
Architecture-specific UAPI Header
```

---

## UAPI Header 的主要來源

Linux Kernel 的 UAPI Header 可以分成：

```text
                    Linux Kernel
                         │
             ┌───────────┴───────────┐
             │                       │
             ▼                       ▼
       include/uapi/          arch/<arch>/include/uapi/
             │                       │
             ▼                       ▼
       Generic UAPI          Architecture UAPI
```

例如 Generic UAPI：

```text
include/uapi/linux/if.h
```

例如 ARM64 UAPI：

```text
arch/arm64/include/uapi/asm/
```

例如 x86 UAPI：

```text
arch/x86/include/uapi/asm/
```

---

## Generic UAPI

Generic UAPI 通常位於：

```text
include/uapi/
```

例如：

```text
include/uapi/linux/if.h
include/uapi/linux/netlink.h
include/uapi/linux/input.h
```

經過 `headers_install` 後：

```text
include/uapi/linux/if.h
            │
            │ headers_install
            ▼
<INSTALL_HDR_PATH>/include/linux/if.h
```

User Space 程式使用：

```c
#include <linux/if.h>
```

---

## Architecture-specific UAPI

不同 Architecture 可以提供自己的 UAPI Header。

例如：

```text
x86:
arch/x86/include/uapi/asm/

ARM64:
arch/arm64/include/uapi/asm/

RISC-V:
arch/riscv/include/uapi/asm/
```

概念：

```text
arch/<arch>/include/uapi/asm/foo.h
                    │
                    │ headers_install
                    ▼
<INSTALL_HDR_PATH>/include/asm/foo.h
```

因此 `uapi/` 是 Kernel Source Tree 的分類目錄。

User Space 最後使用：

```c
#include <asm/foo.h>
```

而不是：

```c
#include <uapi/asm/foo.h>
```

也不是：

```c
#include <arch/arm64/include/uapi/asm/foo.h>
```

---

## `uapi/` 不會出現在最終 Include Path

例如：

```text
arch/x86/include/uapi/asm/boot.h
```

執行：

```bash
make ARCH=x86 headers_install \
    INSTALL_HDR_PATH=/tmp/x86-uapi
```

Export 後：

```text
/tmp/x86-uapi/include/asm/boot.h
```

也就是：

```text
Kernel Source Tree

arch/x86/include/uapi/asm/boot.h
                 │
                 │ headers_install
                 ▼

Exported UAPI

/tmp/x86-uapi/include/asm/boot.h
```

因此 User Space Include：

```c
#include <asm/boot.h>
```

---

## `headers_install` 在做什麼？

Linux Kernel 提供：

```bash
make headers_install
```

將 UAPI Headers Export 成 User Space 可以使用的 Header Tree。

例如 ARM64：

```bash
make ARCH=arm64 headers_install \
    INSTALL_HDR_PATH=/tmp/arm64-uapi
```

結果：

```text
/tmp/arm64-uapi/include/
```

整體流程：

```text
                 Linux Kernel Source
                         │
            ┌────────────┴────────────┐
            │                         │
            ▼                         ▼
      include/uapi/          arch/arm64/include/uapi/
            │                         │
            ▼                         ▼
      Generic UAPI               ARM64 UAPI
            │                         │
            └────────────┬────────────┘
                         │
                         │ headers_install
                         ▼
             /tmp/arm64-uapi/include/
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
            linux/      asm/   asm-generic/
```

例如：

```text
include/uapi/linux/if.h
            │
            ▼
/tmp/arm64-uapi/include/linux/if.h
```

Architecture-specific UAPI：

```text
arch/arm64/include/uapi/asm/*.h
            │
            ▼
/tmp/arm64-uapi/include/asm/*.h
```

## Kernel Source `include/` 與 Exported `include/`

這兩個 `include/` 不一樣。

Kernel Source Tree：

```text
linux/
├── include/
│   ├── linux/
│   ├── uapi/
│   └── generated/
│
└── arch/arm64/include/
    ├── asm/
    ├── uapi/asm/
    └── generated/
```

其中：

```text
include/linux/
        ↓
Kernel Internal Headers

include/uapi/
        ↓
Generic UAPI Headers

include/generated/
        ↓
Build Generated Headers

arch/arm64/include/asm/
        ↓
ARM64 Kernel Headers

arch/arm64/include/uapi/asm/
        ↓
ARM64 UAPI Headers

arch/arm64/include/generated/
        ↓
ARM64 Generated Headers
```

而：

```text
/tmp/arm64-uapi/include/
```

則是 `headers_install` Export 出來的 User Space Header Tree。

因此：

```text
linux/include/
      ↓
Kernel Source Tree

/tmp/arm64-uapi/include/
      ↓
Exported User Space UAPI Headers
```

## `/usr/include` 是什麼？

`/usr/include` 是目前系統安裝給 User Space Development 使用的 Headers。

例如：

```text
/usr/include/stdio.h
/usr/include/linux/if.h
```

它和你自己的 Linux Kernel Source Tree：

```text
linux/
```

不是同一個地方，也不會自動同步。

```text
Linux Kernel Source Tree
        linux/
          │
          │ 不會自動同步
          ╳
          │
          ▼
      /usr/include/
          │
          ▼
   User Space Headers
```

因此修改：

```text
linux/include/uapi/
```

或：

```text
linux/arch/arm64/include/uapi/
```

不代表：

```text
/usr/include/
```

會跟著改變。

---

## ARM64 與 `/usr/include`

在 ARM64 Debian / Ubuntu 上：

```bash
uname -m
```

通常會看到：

```text
aarch64
```

Generic Linux UAPI Header 通常可以看到：

```text
/usr/include/linux/
```

Architecture-specific Header 在 Debian / Ubuntu Multiarch 環境中可能位於：

```text
/usr/include/aarch64-linux-gnu/asm/
```

概念：

```text
ARM64 User Space Headers

/usr/include/
│
├── linux/
│     ↓
│   Generic Linux UAPI
│
└── aarch64-linux-gnu/
      │
      └── asm/
            ↓
          ARM64-specific Headers
```

實際位置取決於 Distribution 與 Toolchain。

可以使用：

```bash
find /usr/include -path '*/asm/*' | head -50
```

查看實際位置。

---

## `asm-generic` 是什麼？

`asm-generic` 是 Linux 提供的 Architecture Generic Header。

例如：

```text
include/uapi/asm-generic/
```

其中：

```text
uapi
 ↓
User-space API

asm-generic
 ↓
Architecture Generic
```

可以理解成：

```text
                    UAPI
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
arch/arm64/include/uapi/   include/uapi/asm-generic/
          │                     │
          ▼                     ▼
 ARM64-specific UAPI       Generic Architecture UAPI
```

Architecture 可以提供自己的實作，也可以使用 `asm-generic` 提供的通用定義。

## 如何驗證 ARM64 UAPI？

最直接的方法：

```bash
cd linux

rm -rf /tmp/arm64-uapi

make ARCH=arm64 headers_install \
    INSTALL_HDR_PATH=/tmp/arm64-uapi
```

查看所有 Exported Headers：

```bash
find /tmp/arm64-uapi/include -type f | sort
```

只看 Architecture-specific Headers：

```bash
find /tmp/arm64-uapi/include/asm -type f | sort
```

因此要確認：

```text
arch/arm64/include/uapi/
```

裡面的 Header 最後如何提供給 User Space，最直接的方法不是查看 `/usr/include`，而是檢查：

```text
INSTALL_HDR_PATH
```

中的 Export 結果。

## 最簡單記法

```text
include/linux/
        ↓
Kernel Internal Header

include/uapi/linux/
        ↓
Generic Linux UAPI


arch/arm64/include/asm/
        ↓
ARM64 Kernel Internal Header

arch/arm64/include/uapi/asm/
        ↓
ARM64 UAPI


include/uapi/asm-generic/
        ↓
Architecture Generic UAPI
```

完整流程：

```text
              Linux Kernel Source
                     │
                     ▼
                UAPI Headers
                     │
                     │
              headers_install
                     │
                     ▼
       <INSTALL_HDR_PATH>/include/
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
        linux/       asm/   asm-generic/
          │          │          │
          ▼          ▼          ▼
       Generic   Architecture  Generic
        UAPI        UAPI       UAPI
```

最後可以記住：

> **`uapi/` 是 Linux Kernel Source Tree 中用來管理 User Space API Header 的目錄。**

> **`make headers_install` 會將 UAPI Headers Export 成 User Space 可以使用的 Header Tree。**

> **Kernel Source Tree 裡的 `uapi/` 不會直接出現在 User Space 的 `#include` Path 中。**

> **`/usr/include` 是系統目前已安裝的 User Space Headers，不會自動與自己的 Linux Kernel Source Tree 同步。**
