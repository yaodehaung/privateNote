# Linux Kernel `olddefconfig`

## 1. `olddefconfig` 是什麼？

`olddefconfig` 是 Linux Kernel Kconfig 系統提供的一個 Makefile target。

使用方式：

```bash
make olddefconfig
```

它的主要功能是：

> 使用目前的 `.config` 作為基礎，保留原本有效的 Kernel 設定，並將缺少或新版 Kernel 新增的 Kconfig 選項自動設定為預設值。

---

## 2. 基本流程

假設目前 Kernel source tree 已經存在：

```text
.config
```

內容可能包含：

```text
CONFIG_NET=y
CONFIG_USB=y
CONFIG_KUNIT=y
CONFIG_RTC_CLASS=y
```

執行：

```bash
make olddefconfig
```

Kconfig 會重新讀取：

```text
.config
        │
        ▼
讀取 Kconfig
        │
        ▼
解析 depends on / select / default
        │
        ▼
保留原本有效設定
        │
        ▼
缺少的設定使用 default
        │
        ▼
產生新的 .config
```

---

## 3. 為什麼需要 `olddefconfig`？

例如原本使用 Linux 6.x：

```text
CONFIG_NET=y
CONFIG_USB=y
```

之後切換到新的 Kernel branch：

```bash
git checkout master
```

新版 Kernel 新增：

```text
CONFIG_NEW_FEATURE
```

舊 `.config` 裡沒有：

```text
CONFIG_NEW_FEATURE
```

這時執行：

```bash
make olddefconfig
```

Kconfig 會依照該選項的 `default` 自動決定設定。

例如：

```Kconfig
config NEW_FEATURE
	bool "New feature"
	default y
```

最後可能得到：

```text
CONFIG_NEW_FEATURE=y
```

不需要人工回答問題。

---

## 4. `oldconfig` 與 `olddefconfig`

### `oldconfig`

```bash
make oldconfig
```

如果遇到新的 Kconfig 選項，會詢問使用者：

```text
New kernel feature (NEW_FEATURE) [Y/n/?]
```

需要手動回答。

### `olddefconfig`

```bash
make olddefconfig
```

遇到新的 Kconfig 選項不會詢問，而是直接採用：

```text
default value
```

因此可以簡單理解成：

```text
oldconfig
    └── 新選項 → 問使用者

olddefconfig
    └── 新選項 → 使用 default
```

## 5. 與 defconfig 搭配

例如 x86_64：

```bash
make x86_64_defconfig
```

會先建立：

```text
.config
```

之後修改一些設定：

```bash
scripts/config --enable KUNIT
scripts/config --enable RTC_CLASS
```

再執行：

```bash
make olddefconfig
```

讓 Kconfig 重新處理設定與相依關係。

流程：

```text
x86_64_defconfig
       │
       ▼
    .config
       │
       ▼
修改 CONFIG_*
       │
       ▼
make olddefconfig
       │
       ▼
更新後的 .config
```

---

## 6. 與 `merge_config.sh` 搭配

Kernel 提供：

```text
scripts/kconfig/merge_config.sh
```

可以把多個 config fragment 合併。

例如：

```text
rtc.config
kunit.config
debug.config
```

`rtc.config`：

```text
CONFIG_RTC_CLASS=y
```

`kunit.config`：

```text
CONFIG_KUNIT=y
```

`debug.config`：

```text
CONFIG_DEBUG_KERNEL=y
```

先建立 base config：

```bash
make x86_64_defconfig
```

再合併：

```bash
scripts/kconfig/merge_config.sh -m .config \
    rtc.config \
    kunit.config \
    debug.config
```

最後：

```bash
make olddefconfig
```

完整流程：

```text
x86_64_defconfig
       │
       ▼
    .config
       │
       ├── rtc.config
       ├── kunit.config
       └── debug.config
       │
       ▼
merge_config.sh
       │
       ▼
    .config
       │
       ▼
make olddefconfig
       │
       ▼
Kconfig 重新處理 dependencies/defaults
       │
       ▼
最終 .config
```

## 7. 常見使用情境

### Kernel 升級

從舊 Kernel 的 config 開始：

```bash
cp /boot/config-$(uname -r) .config
make olddefconfig
```

用新的 Kernel Kconfig 規則更新 `.config`。

### 切換 Git branch

例如：

```bash
git checkout test
make olddefconfig
```

如果新的 branch 增加 Kconfig 選項，可以自動補上設定。

### 套用 Kernel patch

如果 patch 新增：

```Kconfig
config MY_DRIVER
	tristate "My driver"
	default n
```

原本 `.config` 沒有：

```text
CONFIG_MY_DRIVER
```

執行：

```bash
make olddefconfig
```

Kconfig 就會按照：

```text
default n
```

更新 `.config`。

### 合併 config fragment

```bash
make x86_64_defconfig

scripts/kconfig/merge_config.sh -m .config my.config

make olddefconfig
```

這是 Kernel 開發中很常見的使用方式。

## 8. `savedefconfig`

`olddefconfig` 是更新 `.config`：

```bash
make olddefconfig
```

如果想把目前設定整理成精簡的 defconfig，可以：

```bash
make savedefconfig
```

產生：

```text
defconfig
```

因此：

```text
make olddefconfig
        │
        ▼
更新 .config

make savedefconfig
        │
        ▼
產生精簡 defconfig
```

例如：

```bash
make x86_64_defconfig

scripts/kconfig/merge_config.sh -m .config \
    rtc.config \
    kunit.config

make olddefconfig

make savedefconfig
```

最後得到：

```text
defconfig
```

如果要保存成自己的 x86 config：

```bash
mv defconfig arch/x86/configs/broadwell_defconfig
```

之後即可：

```bash
make broadwell_defconfig
```

---

## 9. 總結

`olddefconfig` 可以簡單理解為：

> **使用目前 `.config`，按照現在 Kernel 的 Kconfig 規則重新整理設定，缺少的新選項自動使用 default。**

常見流程：

```bash
make x86_64_defconfig

scripts/kconfig/merge_config.sh -m .config my.config

make olddefconfig
```

如果還要保存新的 defconfig：

```bash
make savedefconfig
```

整體關係：

```text
defconfig
   │
   ▼
.config
   │
   ├── config fragments
   ▼
merge_config.sh
   │
   ▼
.config
   │
   ▼
olddefconfig
   │
   ▼
完整、符合目前 Kconfig 規則的 .config
   │
   ▼
savedefconfig
   │
   ▼
精簡 defconfig
```
