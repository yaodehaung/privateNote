# Linux Kernel：`ip` 與 `devlink` 的差異

Linux 中的 `ip` 和 `devlink` 都是 **Userspace CLI 工具**，也都會透過 **Netlink** 與 Linux Kernel 溝通。

但兩者負責的層級不同：

- `ip`：主要管理 **Linux Network Stack**
- `devlink`：主要管理 **網路硬體與 Network Driver**

---

## 1. 架構差異

### `ip`

```text
Userspace
    │
    │ ip
    ▼
NETLINK_ROUTE
    │
    ▼
Linux Network Stack
    │
    ├── net/core/
    ├── net/ipv4/
    ├── net/ipv6/
    ├── net/8021q/
    └── net/bridge/
          │
          ▼
   struct net_device
          │
          ▼
      NIC Driver
          │
          ▼
      NIC Hardware
```

`ip` 主要是在控制 Linux Kernel 的 Network Stack。

例如：

```bash
ip link set eth0 up

ip addr add 192.168.1.10/24 dev eth0

ip route add default via 192.168.1.1
```

分別是在管理：

```text
ip link
   ↓
Network Interface

ip addr
   ↓
IPv4 / IPv6 Address

ip route
   ↓
Routing Table
```

---

## 2. `devlink`

`devlink` 的架構比較偏向 Driver 與 Hardware：

```text
Userspace
    │
    │ devlink
    ▼
Generic Netlink
    │
    ▼
net/devlink/
    │
    ▼
Devlink Core
    │
    ▼
Network Driver
    │
    ▼
NIC / Switch ASIC
```

例如：

```bash
devlink dev show
```

查看 devlink device。

```bash
devlink port show
```

查看硬體 port。

```bash
devlink resource show
```

查看 driver / hardware resource。

```bash
devlink health show
```

查看 driver 提供的 health reporter。

---

## 3. `ip` vs `devlink`

| 項目 | `ip` | `devlink` |
|---|---|---|
| 主要用途 | Network Stack 管理 | Driver / Hardware 管理 |
| 管理對象 | Network Interface | Network Device |
| Kernel object | `struct net_device` | `struct devlink` |
| Netlink | `NETLINK_ROUTE` | Generic Netlink |
| Kernel 主要位置 | `net/core/` | `net/devlink/` |
| IP Address | ✓ | ✗ |
| Routing | ✓ | ✗ |
| Interface UP/DOWN | ✓ | 通常不是主要用途 |
| Hardware Port | ✗ | ✓ |
| Hardware Resource | ✗ | ✓ |
| Driver Health | ✗ | ✓ |
| Driver Reload | ✗ | ✓ |

---

# 4. 最重要的概念

可以把兩者理解成：

```text
ip
│
└── Linux 怎麼「使用」這張網卡？
        │
        ├── IP
        ├── Route
        ├── Neighbor
        ├── VLAN
        ├── Bridge
        └── Interface


devlink
│
└── 這張「網路硬體 / Driver」怎麼管理？
        │
        ├── Port
        ├── Resource
        ├── Health
        ├── Parameter
        ├── Reload
        └── Hardware configuration
```

因此：

> **`devlink` 不是 `ip` 的新版，也不是用來取代 `ip`。**

它們是在管理不同層級。

# 5. Kernel Source Code

## `ip`

`ip` 使用的 `NETLINK_ROUTE` 會進入 Linux Network Stack。

主要可以研究：

```text
net/
├── core/
├── ipv4/
├── ipv6/
├── bridge/
├── 8021q/
└── sched/
```

例如：

```bash
ip link
```

主要會涉及：

```text
NETLINK_ROUTE
      ↓
RTM_GETLINK
      ↓
rtnetlink
      ↓
struct net_device
```

Kernel 中可以從：

```text
net/core/rtnetlink.c
```

開始追。

---

## `devlink`

Kernel source：

```text
net/devlink/
```

主要架構：

```text
devlink CLI
    │
    ▼
Generic Netlink
    │
    ▼
net/devlink/netlink.c
    │
    ▼
Devlink Core
    │
    ▼
struct devlink
    │
    ▼
Network Driver
```

Driver 如果要支援 devlink，通常會建立並註冊 devlink instance，例如：

```text
devlink_alloc()
      ↓
devlink_register()
      ↓
driver exposes devlink operations
```

所以不是所有 Network Driver 都一定支援 `devlink`。
