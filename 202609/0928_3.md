# Linux Kernel `/sys/kernel/debug/tracing` 使用筆記

## 1. `/sys/kernel/debug/tracing` 是什麼？

`/sys/kernel/debug/tracing` 是 Linux Kernel **Tracing / ftrace subsystem** 提供給 userspace 的控制介面。

可以透過這個目錄：

- 追蹤 Kernel function
- 查看 function call graph
- 啟用 Kernel tracepoint
- 追蹤 scheduler
- 追蹤 network stack
- 追蹤 IRQ
- 追蹤 syscall
- 使用 kprobe / uprobe
- 即時讀取 Kernel trace

基本架構：

```text
Userspace
   │
   │ read / write
   ▼
/sys/kernel/debug/tracing/
   │
   ▼
Linux Kernel Tracing Subsystem
   │
   ├── ftrace
   ├── function tracer
   ├── function_graph tracer
   ├── tracepoint
   ├── kprobe
   └── uprobe
   │
   ▼
Ring Buffer
   │
   ├── trace
   └── trace_pipe
```

# 2. 進入 tracing 目錄

```bash
cd /sys/kernel/debug/tracing
```

查看內容：

```bash
ls
```

常見的重要檔案：

```text
tracing_on
current_tracer
available_tracers
available_filter_functions
set_ftrace_filter
set_ftrace_notrace
set_graph_function
trace
trace_pipe
events/
```

---

# 3. 查看 Kernel 支援哪些 Tracer

```bash
cat available_tracers
```

例如：

```text
hwlat blk mmiotrace function_graph wakeup_dl wakeup_rt wakeup function nop
```

其中最常使用：

```text
function
function_graph
nop
```

### `function`

追蹤 Kernel function 被呼叫的情況。

### `function_graph`

除了 function 呼叫之外，也可以看到：

```text
function A
   └── function B
         └── function C
```

這種 function call hierarchy。

### `nop`

不使用 function tracer。

通常可以拿來搭配 tracepoint：

```bash
echo nop > current_tracer
```

---

# 4. `tracing_on`

`tracing_on` 是 tracing 的總開關。

查看：

```bash
cat tracing_on
```

如果：

```text
1
```

代表 tracing 開啟。

如果：

```text
0
```

代表 tracing 停止。

開啟：

```bash
echo 1 > tracing_on
```

停止：

```bash
echo 0 > tracing_on
```

---

# 5. 清除 Trace Buffer

查看目前 trace：

```bash
cat trace
```

清空：

```bash
echo > trace
```

一般開始實驗前建議：

```bash
echo 0 > tracing_on
echo > trace
```

---

# 6. Function Tracing

設定：

```bash
echo function > current_tracer
```

開始：

```bash
echo 1 > tracing_on
```

執行一些操作，例如：

```bash
ping 8.8.8.8
```

停止：

```bash
echo 0 > tracing_on
```

查看：

```bash
cat trace
```

可能看到：

```text
bash-1234 [001] .... do_sys_openat2
bash-1234 [001] .... path_openat
bash-1234 [001] .... vfs_open
```

---

# 7. 不要直接 Trace 所有 Function

直接：

```bash
echo function > current_tracer
echo 1 > tracing_on
```

通常會產生大量資料。

比較好的方式是使用：

```text
set_ftrace_filter
```

限制只追蹤特定 function。

---

# 8. `available_filter_functions`

先查看某個 function 能不能被 ftrace：

```bash
grep netif_receive_skb available_filter_functions
```

例如：

```text
netif_receive_skb
netif_receive_skb_list
netif_receive_skb_core
```

如果 function 出現在：

```text
available_filter_functions
```

通常就可以加入：

```text
set_ftrace_filter
```

---

# 9. `set_ftrace_filter`

例如只追：

```c
netif_receive_skb()
```

設定：

```bash
echo netif_receive_skb > set_ftrace_filter
```

確認：

```bash
cat set_ftrace_filter
```

接著：

```bash
echo function > current_tracer
echo 1 > tracing_on
```

查看：

```bash
cat trace_pipe
```

停止：

```bash
echo 0 > tracing_on
```

清除 filter：

```bash
echo > set_ftrace_filter
```

---

# 10. 同時追蹤多個 Function

可以使用：

```bash
echo netif_receive_skb > set_ftrace_filter
echo ip_rcv >> set_ftrace_filter
echo tcp_v4_rcv >> set_ftrace_filter
```

注意：

```bash
>
```

是覆蓋。

而：

```bash
>>
```

是追加。

查看：

```bash
cat set_ftrace_filter
```

---

# 11. 使用 wildcard

例如：

```bash
echo 'tcp_*' > set_ftrace_filter
```

或者：

```bash
echo 'netif_*' > set_ftrace_filter
```

可以一次追蹤一系列 function。

先確認：

```bash
grep '^tcp_' available_filter_functions
```

---

# 12. `set_ftrace_notrace`

如果想排除某些 function：

```bash
echo function > current_tracer
```

然後：

```bash
echo some_function > set_ftrace_notrace
```

意思是：

```text
function tracer
       │
       ├── function A
       ├── function B
       ├── function C
       │
       └── 排除 some_function
```

清除：

```bash
echo > set_ftrace_notrace
```

---

# 13. Function Graph

如果想知道：

```text
netif_receive_skb()
```

裡面又呼叫了哪些 function，可以使用：

```bash
echo function_graph > current_tracer
```

指定入口：

```bash
echo netif_receive_skb > set_graph_function
```

開始：

```bash
echo 1 > tracing_on
```

產生 network traffic：

```bash
ping 8.8.8.8
```

停止：

```bash
echo 0 > tracing_on
```

查看：

```bash
cat trace
```

可能看到：

```text
netif_receive_skb() {
    netif_receive_skb_internal() {
        __netif_receive_skb() {
            __netif_receive_skb_one_core();
        }
    }
}
```

這非常適合研究 Kernel call path。

---

# 14. `trace` vs `trace_pipe`

兩個都可以查看 tracing 資料，但用途不同。

## `trace`

```bash
cat trace
```

查看目前 ring buffer 裡面的內容。

適合：

```text
開始 tracing
    ↓
執行測試
    ↓
停止 tracing
    ↓
cat trace
```

---

## `trace_pipe`

```bash
cat trace_pipe
```

是即時讀取。

流程：

```text
Kernel
   ↓
Tracing Ring Buffer
   ↓
trace_pipe
   ↓
terminal
```

適合即時 debug。

例如：

Terminal 1：

```bash
cat /sys/kernel/debug/tracing/trace_pipe
```

Terminal 2：

```bash
ping 8.8.8.8
```

Terminal 1 就會持續看到新的 tracing event。

# 17. 啟用一個 Trace Event

例如：

```bash
echo 1 > events/net/netif_receive_skb/enable
```

查看：

```bash
cat trace_pipe
```

然後：

```bash
ping 8.8.8.8
```

就可以觀察 network receive event。

關閉：

```bash
echo 0 > events/net/netif_receive_skb/enable
```

---

# 18. 啟用整個 Network Event Group

可以直接：

```bash
echo 1 > events/net/enable
```

這代表：

```text
events/net/
   ├── event A
   ├── event B
   ├── event C
   └── ...
```

全部啟用。

關閉：

```bash
echo 0 > events/net/enable
```

# 19. Scheduler Trace

查看：

```bash
ls events/sched/
```

常見：


例如追蹤 context switch：

```bash
echo 1 > events/sched/sched_switch/enable
```


# 20. Syscall Trace

查看：

```bash
ls events/syscalls/
```

例如：

```text
sys_enter_openat
sys_exit_openat

```

開啟：

```bash
echo 1 > events/syscalls/sys_enter_openat/enable
```


```bash
cat /etc/passwd
```

# 21. Network Stack 實驗

如果正在研究：

```text
Network Driver
     ↓
NAPI
     ↓
netif_receive_skb()
     ↓
Ethernet
     ↓
IP
     ↓
TCP / UDP
     ↓
Socket
```

可以從：

```bash
grep netif_receive_skb available_filter_functions
```

開始。

設定：

```bash
echo 0 > tracing_on
echo > trace

echo function_graph > current_tracer
echo netif_receive_skb > set_graph_function

echo 1 > tracing_on
```

產生封包：

```bash
ping 8.8.8.8
```

停止：

```bash
echo 0 > tracing_on
```

查看：

```bash
less trace
```

就可以研究：

```text
netif_receive_skb()
        │
        ▼
network stack
        │
        ▼
IP layer
        │
        ▼
protocol processing
```

# 22. 一套標準 Ftrace Debug 流程

我通常會用：

```bash
cd /sys/kernel/debug/tracing

echo 0 > tracing_on

echo nop > current_tracer

echo > trace
echo > set_ftrace_filter
echo > set_ftrace_notrace
echo > set_graph_function

echo function_graph > current_tracer

echo target_function > set_graph_function

echo 1 > tracing_on
```

執行測試。

然後：

```bash
echo 0 > tracing_on
cat trace
```

最後恢復：

```bash
echo nop > current_tracer
echo > set_ftrace_filter
echo > set_ftrace_notrace
echo > set_graph_function
```

# 23. `/sys/kernel/debug/tracing` 重要架構

```text
/sys/kernel/debug/tracing/
│
├── tracing_on
│      │
│      └── tracing 總開關
│
├── current_tracer
│      │
│      └── 選擇 tracer
│
├── available_tracers
│      │
│      └── Kernel 支援的 tracer
│
├── available_filter_functions
│      │
│      └── 可以被 function tracer 追蹤的 functions
│
├── set_ftrace_filter
│      │
│      └── 指定要追蹤的 functions
│
├── set_ftrace_notrace
│      │
│      └── 排除 functions
│
├── set_graph_function
│      │
│      └── function_graph 的入口 function
│
├── events/
│      │
│      ├── sched/
│      ├── net/
│      ├── irq/
│      ├── kmem/
│      ├── skb/
│      └── syscalls/
│
├── trace
│      │
│      └── 查看目前 trace buffer
│
└── trace_pipe
       │
       └── 即時讀取 tracing 資料
```

# 24. 核心概念

可以把整個 tracing subsystem 理解成：

```text
                Linux Kernel
                     │
          ┌──────────┴──────────┐
          │                     │
       Function              Tracepoint
          │                     │
          ▼                     ▼
       ftrace                 events/
          │                     │
          └──────────┬──────────┘
                     ▼
               Ring Buffer
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
        trace               trace_pipe
          │                     │
          ▼                     ▼
     事後分析                即時分析
```

因此 `/sys/kernel/debug/tracing` 最重要的幾個東西可以先記：

```text
tracing_on
current_tracer
set_ftrace_filter
set_graph_function
events/
trace
trace_pipe
```

如果要研究 Linux Kernel function 的執行流程，優先學：

```text
function
function_graph
```

如果要研究 Kernel subsystem 的行為，優先學：

```text
tracepoint
events/
```

例如研究 Linux networking，可以組合：

```text
ftrace
   +
function_graph
   +
net tracepoint
   +
trace_pipe
```

來觀察：

```text
Network Driver
      ↓
NAPI
      ↓
SKB
      ↓
Network Stack
      ↓
IPv4 / IPv6
      ↓
TCP / UDP
      ↓
Socket
```
