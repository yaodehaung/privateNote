# Linux Network Namespace：如何確認目前所在的 Namespace

## 1. Network Namespace 是什麼？

Linux Network Namespace（netns）可以讓不同 process 擁有彼此隔離的網路環境。

每個 Network Namespace 可以有自己的：

```text
Network Namespace
├── Network Interface
├── IPv4 / IPv6 Address
├── Routing Table
├── ARP / Neighbour Table
├── Socket
└── Network configuration
```

例如：

```text
Linux Kernel
│
├── Default Namespace
│     └── eth0
│
├── nsA
│     └── vethA
│          └── 192.168.10.1/24
│
└── nsB
      └── vethB
           └── 192.168.10.2/24
```

---

# 2. 查看目前有哪些 Network Namespace

使用：

```bash
ip netns list
```

例如：

```text
nsA
nsB
```

代表目前建立了兩個具名 Network Namespace。

---

# 3. 查看目前 Process 的 Network Namespace

Linux 會在 `/proc` 提供 process 的 namespace 資訊。

執行：

```bash
readlink /proc/self/ns/net
```

例如：

```text
net:[4026531840]
```

其中：

```text
4026531840
```

可以用來識別這個 Network Namespace。

---

# 4. 比較不同 Namespace

查看目前 shell：

```bash
readlink /proc/self/ns/net
```

查看 `nsA`：

```bash
sudo ip netns exec nsA readlink /proc/self/ns/net
```

查看 `nsB`：

```bash
sudo ip netns exec nsB readlink /proc/self/ns/net
```

例如：

```text
Default    net:[4026531840]
nsA        net:[4026532701]
nsB        net:[4026532702]
```

因為 ID 不同，所以代表：

```text
Default Namespace
       │
       └── net:[4026531840]

nsA
       │
       └── net:[4026532701]

nsB
       │
       └── net:[4026532702]
```

它們是三個不同的 Network Namespace。

---

# 5. 查看目前 Namespace 的名稱

可以使用：

```bash
ip netns identify $$
```

其中：

```text
$$
```

代表目前 shell 的 PID。

如果目前 shell 位於 `nsA`，可能輸出：

```text
nsA
```

如果目前位於 default network namespace，通常可能沒有輸出。

---

# 6. 進入 nsA

可以直接啟動一個位於 `nsA` 的 shell：

```bash
sudo ip netns exec nsA bash
```

現在執行：

```bash
ip netns identify $$
```

可能看到：

```text
nsA
```

也可以：

```bash
readlink /proc/self/ns/net
```

例如：

```text
net:[4026532701]
```

---

# 7. 查看 nsA 的 Network Interface

進入 `nsA` 後：

```bash
ip addr
```

例如：

```text
1: lo: <LOOPBACK,UP>

2: vethA: <BROADCAST,MULTICAST,UP,LOWER_UP>
    inet 192.168.10.1/24
```

此時你看到的是：

```text
nsA
│
├── lo
│
└── vethA
      └── 192.168.10.1/24
```

而不是 default namespace 裡面的網卡。

---

# 8. 查看 Routing Table

在 `nsA`：

```bash
ip route
```

可能看到：

```text
192.168.10.0/24 dev vethA proto kernel scope link src 192.168.10.1
```

而在 `nsB`：

```bash
sudo ip netns exec nsB ip route
```

可能看到：

```text
192.168.10.0/24 dev vethB proto kernel scope link src 192.168.10.2
```

兩個 namespace 有自己的 routing context。

---

# 9. nsA Ping nsB

假設：

```text
nsA                              nsB

192.168.10.1                     192.168.10.2
     │                                │
   vethA ========================== vethB
                 veth pair
```

可以：

```bash
sudo ip netns exec nsA ping 192.168.10.2
```

或者先進入：

```bash
sudo ip netns exec nsA bash
```

再：

```bash
ping 192.168.10.2
```

封包概念上：

```text
nsA
│
│ ping 192.168.10.2
│
▼
ICMP
│
▼
IPv4 Stack
│
▼
vethA
│
│
│ veth pair
│
▼
vethB
│
▼
IPv4 Stack
│
▼
ICMP
│
▼
nsB
192.168.10.2
```

---

# 10. 離開 Network Namespace

如果是使用：

```bash
sudo ip netns exec nsA bash
```

進入的，直接：

```bash
exit
```

即可回到原本的 Network Namespace。

然後：

```bash
ip netns identify $$
```

通常就不再顯示：

```text
nsA
```

---

# 11. Network Namespace 與 Process 的關係

Network Namespace 是跟 process 關聯的。

Kernel 裡可以概念化成：

```text
bash process
     │
     ▼
struct task_struct
     │
     ▼
struct nsproxy
     │
     ▼
    net_ns
     │
     ▼
 struct net
```

Kernel source 可以從：

```text
include/net/net_namespace.h
```

開始研究。

其中很重要的資料結構是：

```c
struct net;
```

---

# 12. `/proc/<PID>/ns/net`

每個 process 都可以查看自己的 Network Namespace：

```text
/proc/<PID>/ns/net
```

例如目前 shell：

```bash
echo $$
```

假設：

```text
12345
```

查看：

```bash
readlink /proc/12345/ns/net
```

也可以直接：

```bash
readlink /proc/self/ns/net
```

其中：

```text
self
```

代表目前正在執行這個命令的 process。

---

# 13. 常用指令整理

查看所有具名 Network Namespace：

```bash
ip netns list
```

查看目前 Network Namespace ID：

```bash
readlink /proc/self/ns/net
```

查看目前具名 Network Namespace：

```bash
ip netns identify $$
```

進入 `nsA`：

```bash
sudo ip netns exec nsA bash
```

直接在 `nsA` 執行命令：

```bash
sudo ip netns exec nsA ip addr
```

查看 `nsA` routing table：

```bash
sudo ip netns exec nsA ip route
```

從 `nsA` ping `nsB`：

```bash
sudo ip netns exec nsA ping 192.168.10.2
```

離開 namespace shell：

```bash
exit
```

---

# 14. 整體架構

最重要的觀念是：

```text
                    Linux Kernel
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼

 Default netns          nsA              nsB
        │                │                │
      eth0             vethA            vethB
                         │                │
                         │  veth pair     │
                         └────────────────┘
                         │                │
                  192.168.10.1     192.168.10.2
```

`nsA` 和 `nsB` 看起來像兩台不同的 Linux 主機：

```text
Virtual Host A                     Virtual Host B
     │                                  │
192.168.10.1                       192.168.10.2
     │                                  │
   vethA ============================ vethB
```

但實際上：

```text
nsA ──┐
      │
nsB ──┼──→ 共用同一個 Linux Kernel
      │
Host ─┘
```

因此 Network Namespace 很適合拿來研究：

```text
IPv4 / IPv6
Routing
ARP / Neighbour
ICMP
TCP / UDP
Bridge
VLAN
Netfilter
Network Driver
Network Stack
Container Networking
```

尤其要研究 Linux Kernel `net/ipv4/` 時，可以使用：

```text
nsA
192.168.10.1
   │
 vethA
   │
   │ packet
   ▼
 vethB
   │
192.168.10.2
nsB
```

再配合：

```text
tcpdump
ftrace
tracepoint
perf
eBPF
```

觀察封包實際如何經過 Linux Kernel Network Stack。
