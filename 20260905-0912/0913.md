# Linux Kernel `pr_debug()` 與 Dynamic Debug

**Author:** Nick Huang
**Date:** 2026-09-13

---

## 1. `pr_debug()` 是什麼？

Linux Kernel 可以使用：

```c id="f04ghh"
pr_debug("debug message\n");
```

輸出除錯訊息。

但 `pr_debug()` 和 `pr_info()` 不同，通常預設不會輸出。

例如：

```c id="bhnwj1"
pr_info("info message\n");
pr_debug("debug message\n");
```

一般情況：

```text id="k3b00y"
pr_info()
   ↓
直接輸出

pr_debug()
   ↓
預設關閉
```

要控制 `pr_debug()`，可以使用 Linux Kernel 的 **Dynamic Debug** 機制。

---

## 2. 確認 Dynamic Debug

先檢查目前 Kernel：

```bash id="9wbq8i"
grep CONFIG_DYNAMIC_DEBUG /boot/config-$(uname -r)
```

或在 Kernel source：

```bash id="12k8gl"
grep CONFIG_DYNAMIC_DEBUG .config
```

需要：

```text id="bxqfnh"
CONFIG_DYNAMIC_DEBUG=y
```

如果沒有：

```bash id="1lzgfn"
./scripts/config --enable DYNAMIC_DEBUG
make olddefconfig
```

之後重新 Build Kernel。

---

## 3. Dynamic Debug Control

Dynamic Debug 的控制介面通常可以從：

```text id="75ug94"
/proc/dynamic_debug/control
```

或：

```text id="v6lx1p"
/sys/kernel/debug/dynamic_debug/control
```

找到。

例如：

```bash id="k6akj7"
ls /proc/dynamic_debug/control
```

查看所有 Dynamic Debug callsite：

```bash id="1nplxn"
cat /proc/dynamic_debug/control
```

---

## 4. 開啟 `debug_vm_pgtable.c` 的 `pr_debug()`

例如要開：

```text id="q1akz5"
mm/debug_vm_pgtable.c
```

執行：

```bash id="9x1af5"
echo 'file mm/debug_vm_pgtable.c +p' | \
sudo tee /proc/dynamic_debug/control
```

其中：

```text id="l9mtjz"
+p
```

代表啟用該 callsite 的輸出。

接著查看 Kernel log：

```bash id="nxv8xu"
sudo dmesg -w
```

---

## 5. 確認是否成功 Enable

```bash id="zgyp9m"
grep 'mm/debug_vm_pgtable.c' /proc/dynamic_debug/control
```

可能看到：

```text id="p0mhnk"
mm/debug_vm_pgtable.c:xxx [kernel]function_name =p "message"
```

其中：

```text id="wexi1u"
=_    → disabled
=p    → enabled
```

---

## 6. 關閉 `pr_debug()`

```bash id="z7n7xl"
echo 'file mm/debug_vm_pgtable.c -p' | \
sudo tee /proc/dynamic_debug/control
```

---

# Reboot 後保留 Dynamic Debug

Runtime 執行：

```bash id="km47my"
echo 'file mm/debug_vm_pgtable.c +p' > /proc/dynamic_debug/control
```

只修改目前 Kernel 的狀態：

```text id="zyay37"
+p
 ↓
目前有效
 ↓
reboot
 ↓
設定消失
```

如果希望重新開機之後仍然自動 Enable，需要使用 Kernel Command Line。

---

## 7. 使用 `dyndbg` Kernel Parameter

編輯 GRUB：

```bash id="x7k40x"
sudo nano /etc/default/grub
```

找到：

```text id="h8y32q"
GRUB_CMDLINE_LINUX_DEFAULT="..."
```

加入：

```text id="o40j8d"
dyndbg="file mm/debug_vm_pgtable.c +p"
```

例如：

```text id="j83r04"
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash dyndbg=\"file mm/debug_vm_pgtable.c +p\""
```

更新：

```bash id="2lj3zn"
sudo update-grub
sudo reboot
```

---

## 8. Reboot 後確認

查看 Kernel command line：

```bash id="pov1px"
cat /proc/cmdline
```

確認存在：

```text id="24u0qa"
dyndbg=file mm/debug_vm_pgtable.c +p
```

再檢查：

```bash id="uzm8ya"
grep 'mm/debug_vm_pgtable.c' /proc/dynamic_debug/control
```

成功 Enable 的 callsite flag 會包含：

```text id="ggaz55"
=p
```

查看這次 boot 的 log：

```bash id="kbb9jm"
sudo dmesg | grep -i pgtable
```

或：

```bash id="gzb6qm"
sudo journalctl -k -b | grep -i pgtable
```

## 9. 為什麼 `debug_vm_pgtable` 建議 Boot 時 Enable？

如果 `debug_vm_pgtable` 在 Kernel initialization 階段執行：

```text id="r12t4c"
Kernel Boot
     ↓
Dynamic Debug
     ↓
debug_vm_pgtable()
     ↓
Page Table Helper Tests
     ↓
pr_debug()
     ↓
Boot 完成
```

如果 Linux Boot 完才執行：

```bash id="63pz9q"
echo 'file mm/debug_vm_pgtable.c +p' > /proc/dynamic_debug/control
```

可能已經太晚：

```text id="stvr65"
Kernel Boot
     ↓
debug_vm_pgtable()
     ↓
pr_debug() disabled
     ↓
測試完成
     ↓
Linux Boot 完成
     ↓
使用者設定 +p
```

因此 `debug_vm_pgtable` 這類 boot/init 階段的程式，使用：

```text id="hpm9gz"
dyndbg="file mm/debug_vm_pgtable.c +p"
```

會比較適合。

## 11. `DEBUG_VM_PGTABLE` vs `PTDUMP_DEBUGFS`

兩者用途不同：

| Config                    | 用途                     |
| ------------------------- | ---------------------- |
| `CONFIG_DEBUG_VM_PGTABLE` | 測試 Page Table Helper   |
| `CONFIG_PTDUMP_DEBUGFS`   | Dump Kernel Page Table |

### `DEBUG_VM_PGTABLE`

概念：

```text id="e1acgn"
CONFIG_DEBUG_VM_PGTABLE
        ↓
Page Table Helper Self-test
        ↓
PTE / PMD / PUD
        ↓
pte_young()
pte_mkyoung()
pte_mkold()
pte_dirty()
pte_mkdirty()
pte_mkclean()
...
```

主要目的是測試 Architecture 提供的 Page Table Helper 是否符合 Linux MM 預期的語意。

### `PTDUMP_DEBUGFS`

概念：

```text id="o0ts16"
CONFIG_PTDUMP_DEBUGFS
        ↓
Page Table Dump
        ↓
debugfs
        ↓
kernel_page_tables
```

如果 Architecture 支援，可以設定：

```bash id="jvkp1u"
./scripts/config --enable PTDUMP_DEBUGFS
make olddefconfig
```

確認：

```bash id="f5gj6s"
grep CONFIG_PTDUMP .config
```

可能看到：

```text id="9eyslv"
CONFIG_PTDUMP_CORE=y
CONFIG_PTDUMP_DEBUGFS=y
```

## 12. 整體關係

```text id="k86xym"
                 Linux Kernel
                      │
          ┌───────────┴───────────┐
          │                       │
          ▼                       ▼
 DEBUG_VM_PGTABLE           PTDUMP_DEBUGFS
          │                       │
          ▼                       ▼
 Page Table Helper            Page Table
     Self-test                   Dump
          │                       │
          ▼                       ▼
 PTE / PMD / PUD         kernel_page_tables
          │
          ▼
      pr_debug()
          │
          ▼
    Dynamic Debug
          │
      ┌───┴────┐
      │        │
 runtime +p  dyndbg=
      │        │
      ▼        ▼
目前啟用     Boot 時啟用
               │
               ▼
         debug_vm_pgtable
         early/init testing
```

## 13. 常用指令

Runtime 開啟：

```bash id="e6amkf"
echo 'file mm/debug_vm_pgtable.c +p' | \
sudo tee /proc/dynamic_debug/control
```

Runtime 關閉：

```bash id="tl8nnb"
echo 'file mm/debug_vm_pgtable.c -p' | \
sudo tee /proc/dynamic_debug/control
```

確認：

```bash id="c4yupx"
grep 'mm/debug_vm_pgtable.c' /proc/dynamic_debug/control
```

即時查看 Kernel log：

```bash id="03uvv8"
sudo dmesg -w
```

Boot 時自動開啟：

```text id="dx98db"
dyndbg="file mm/debug_vm_pgtable.c +p"
```

套用 GRUB：

```bash id="sqnn0w"
sudo update-grub
sudo reboot
```

重新開機後：

```bash id="x8b1e3"
cat /proc/cmdline

grep 'mm/debug_vm_pgtable.c' \
    /proc/dynamic_debug/control

sudo dmesg | grep -i pgtable
```
