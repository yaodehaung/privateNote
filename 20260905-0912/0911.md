# MGLRU vs DAMON

MGLRU（Multi-Gen LRU）和 DAMON（Data Access MONitor）都會碰到 Memory 的 Hot / Cold 判斷，但兩者的定位不同。

> **MGLRU = Kernel 的 Page Reclaim 演算法。**  
> **DAMON = Memory Access Pattern 的監控框架，搭配 DAMOS 可以做 Reclaim 等動作。**

## 比較

| 項目 | MGLRU | DAMON |
|---|---|---|
| 全名 | Multi-Gen LRU | Data Access MONitor |
| 核心目的 | 決定哪些 Folio / Page 該 Reclaim | 低 Overhead 監控 Data Access Pattern |
| 主要角色 | Memory Reclaim | Monitoring + Policy |
| Hot / Cold 判斷 | 有 | 有 |
| 直接參與 Reclaim | 是 | DAMOS `PAGEOUT` 時可以 |
| 粒度 | Folio / Page + Generations | Address Regions |
| 是否需要使用者設定 Policy | 通常不用 | DAMOS 通常需要 |
| 主要程式碼 | `mm/vmscan.c` | `mm/damon/` |

---

## MGLRU

MGLRU 解決的是：

```text
Memory Pressure
      ↓
哪些 Folio 最近常用？
哪些 Folio 很久沒用？
      ↓
MGLRU Generations

Gen 5   ← Newer / Hotter
Gen 4
Gen 3
Gen 2
Gen 1   ← Older / Colder
      ↓
Reclaim Old Generations
```

# 補充資料

# CONFIG_DEBUG_VM_PGTABLE

`CONFIG_DEBUG_VM_PGTABLE` 的主要用途是：

> **測試 Linux 各 Architecture 實作的 Page Table Helper 是否符合 Linux MM Core 預期的語意。**

它不是用來查看某個 Process 的 Page Table，而比較像是：

> **Page Table API 的 Self-test / Sanity Test**

---

## 測試哪些 Page Table Helper？

Architecture 通常會提供很多 Page Table Helper，例如：

```c
pte_young()
pte_mkyoung()
pte_mkold()

pte_dirty()
pte_mkdirty()
pte_mkclean()

pte_write()
pte_mkwrite()
pte_wrprotect()

pte_present()

pmd_young()
pmd_mkyoung()
pmd_mkold()
```

`CONFIG_DEBUG_VM_PGTABLE` 會建立測試用的 Page Table Entry，檢查這些 Helper 的行為是否正確。

---

## 例如測試 Young / Old

概念流程：

```text
建立 PTE
   ↓
pte_mkyoung()
   ↓
檢查 pte_young() == true
   ↓
pte_mkold()
   ↓
檢查 pte_young() == false
```

概念程式：

```c
pte_t pte;

pte = pte_mkyoung(pte);

WARN_ON(!pte_young(pte));

pte = pte_mkold(pte);

WARN_ON(pte_young(pte));
```

如果：

```c
pte_mkold()
```

沒有正確清除 Young / Accessed 狀態：

```text
pte_mkyoung()
      ↓
PTE = Young
      ↓
pte_mkold()
      ↓
理論上應該變 Old
      ↓
pte_young()
      ↓
竟然還是 true
      ↓
DEBUG_VM_PGTABLE
      ↓
WARN / Test Failure
```

---

## 主要測試內容

| 類型 | 測試內容 |
|---|---|
| Young / Accessed | `pte_young()`、`pte_mkyoung()`、`pte_mkold()` |
| Dirty | `pte_dirty()`、`pte_mkdirty()`、`pte_mkclean()` |
| Write Permission | `pte_write()`、`pte_mkwrite()`、`pte_wrprotect()` |
| Present | PTE 是否為 Present |
| PMD / PUD | Higher-level Page Table Entry 操作 |
| Huge Page | Huge Page 相關 Entry 操作 |
| Swap Entry | Swap PTE Conversion / Helper |
| Page Table Bits | Architecture-specific Bit 操作 |

## 和 Architecture 的關係

Linux MM Core 定義 Page Table Helper 應該具有什麼語意。

實際實作則由不同 Architecture 負責：

```text
              Linux MM Core
                   │
          Page Table API 語意
                   │
                   ▼
          <asm/pgtable.h>
                   │
       ┌───────────┼───────────┐
       ▼           ▼           ▼
      x86        arm64       riscv
       │           │           │
       ▼           ▼           ▼
arch/x86/      arch/arm64/   arch/riscv/
include/asm/   include/asm/  include/asm/
pgtable.h      pgtable.h     pgtable.h
       │           │           │
       └───────────┼───────────┘
                   ▼
          DEBUG_VM_PGTABLE
                   │
                   ▼
      測試 Architecture Implementation
      是否符合 Linux MM 的預期
```

例如：

```text
arch/arm64/include/asm/pgtable.h
arch/x86/include/asm/pgtable.h
arch/riscv/include/asm/pgtable.h
```

都可能提供各自 Architecture 的 Page Table Helper。

---

## 和 DAMON 的關係

DAMON 會使用 Page Table Helper 判斷 Memory 是否被 Access。

例如：

```c
pte_young()
pte_mkold()
```

概念：

```text
PTE
 │
 ├── pte_young()
 │      ↓
 │   檢查最近是否 Access
 │
 └── pte_mkold()
        ↓
     清除 Young 狀態
        ↓
     等待下一次 Access
        ↓
     CPU 再次 Access
        ↓
     PTE 重新變成 Young
        ↓
     再使用 pte_young() 檢查
```

因此：

```text
CONFIG_DEBUG_VM_PGTABLE
        ↓
驗證 pte_young() / pte_mkold()
等 Page Table Helper
        ↓
Architecture Page Table 實作正確
        ↓
DAMON 等 MM Subsystem
可以正確使用這些 Helper
```

---

## DAMON Access Monitoring 範例

DAMON 想知道某個 Memory Region 最近有沒有被 Access。

概念上可以：

```text
第一次 Sample
      ↓
pte_mkold()
      ↓
清除 Accessed / Young 狀態
      ↓
等待一段時間
      ↓
CPU Access Memory
      ↓
Hardware 更新 Accessed / Young
      ↓
pte_young()
      ↓
true
      ↓
知道這個 Memory 最近被 Access
```

如果 CPU 沒有再次 Access：

```text
pte_mkold()
      ↓
PTE = Old
      ↓
等待
      ↓
沒有 Memory Access
      ↓
pte_young()
      ↓
false
      ↓
這段 Memory 最近沒有被 Access
```

因此 `pte_young()` / `pte_mkold()` 的 Architecture Implementation 是否正確，會影響 DAMON 的 Access Monitoring。

---

## 為什麼需要 CONFIG_DEBUG_VM_PGTABLE？

Linux 支援很多 Architecture：

```text
x86
arm
arm64
riscv
powerpc
s390
loongarch
...
```

Linux MM Core 不希望知道每個 CPU 的 Page Table Bit 長什麼樣。

所以 MM Core 使用統一 API：

```c
pte_young()
pte_mkyoung()
pte_mkold()
pte_dirty()
pte_write()
pte_present()
```

Architecture 再負責實作：

```text
Linux MM
   │
   │ Generic Page Table API
   ▼
pte_young()
pte_mkold()
pte_write()
...
   │
   ▼
<asm/pgtable.h>
   │
   ├── x86 implementation
   ├── ARM64 implementation
   ├── RISC-V implementation
   └── ...
```

這樣 MM subsystem，例如：

```text
DAMON
MGLRU
Page Reclaim
Migration
mprotect
HugeTLB
THP
```

就可以使用統一的 Page Table API。

而 `CONFIG_DEBUG_VM_PGTABLE` 的工作就是幫忙驗證：

```text
Generic MM API
      ↓
Architecture Implementation
      ↓
行為是否符合預期？
```

---

## 適合什麼時候使用？

特別適合：

```text
開發新的 Architecture
        │
        ▼
實作 <asm/pgtable.h>
        │
        ▼
實作 PTE / PMD / PUD Helper
        │
        ▼
CONFIG_DEBUG_VM_PGTABLE
        │
        ▼
測試 Page Table Primitive
        │
        ▼
確認行為符合 Linux MM 預期
```

或者你修改：

```text
arch/<ARCH>/include/asm/pgtable.h
```

裡面的 Page Table Helper 時，也可以利用相關測試檢查是否破壞既有語意。

---

## 一句話

> **`CONFIG_DEBUG_VM_PGTABLE` = 測試 Architecture-specific Page Table Helper Implementation 是否符合 Linux MM Page Table API 的預期。**

可以把整體關係記成：

```text
                Linux MM
                    │
                    ▼
          Generic Page Table API
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
         x86      ARM64     RISC-V
          │         │         │
          ▼         ▼         ▼
       pgtable.h  pgtable.h  pgtable.h
          │         │         │
          └─────────┼─────────┘
                    ▼
          CONFIG_DEBUG_VM_PGTABLE
                    │
                    ▼
          驗證 Helper 行為是否正確
                    │
                    ▼
          DAMON / MM 可以可靠使用
```
